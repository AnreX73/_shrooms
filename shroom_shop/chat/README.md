# Чат с посетителями

Чат на Django Channels и WebSocket: текст, фото и голосовые сообщения до
60 секунд. Гость привязан к серверной сессии, сотрудник отвечает из виджета
на любой странице или со страницы «Диалоги».

Подробности: [`docs/chat.md`](../docs/chat.md).

## Как устроено

- `Conversation` — диалог. Гость привязан к серверной сессии
  (`request.session["chat_conversation"]`), поэтому подменить чужой диалог из
  браузера нельзя. Авторизованный посетитель дополнительно связывается с
  аккаунтом. Сообщения хранятся в `Message`, повторная отправка отсекается по
  `client_id` (уникальное ограничение в БД).
- `Message` может содержать текст, фото (`image`) и голосовое (`audio`).
  Файлы идут отдельным HTTP-запросом, не через WebSocket.
- `chat/widget.html` — плавающий виджет для посетителей. Подключён в
  `shop/base.html`, `blog/base.html`.
- `chat/operator_widget.html` — плавающая панель оператора со списком диалогов.
  Подключена в `shop/base.html`, `dashboard/base.html`, `blog/base.html`
  для сотрудников (`is_staff`).
- `/chat/operator/` — отдельная страница со списком диалогов,
  `/chat/operator/<uuid>/` — переписка с конкретным посетителем.

WebSocket-адреса:

| Адрес | Кто подключается |
|---|---|
| `/ws/chat/` | посетитель (диалог берётся из сессии) |
| `/ws/chat/operator/` | оператор: живой список диалогов |
| `/ws/chat/operator/<uuid>/` | оператор: переписка с посетителем |

HTTP-загрузки:

| Адрес | Кто |
|---|---|
| `POST /chat/upload/` | посетитель |
| `POST /chat/operator/<uuid>/upload/` | оператор |

## Права

Отвечать в чате могут все сотрудники с `is_staff`. Отдельное право
`chat.reply_conversation` больше не используется.

## Статусы и хранение

- Бейджи: «Гость», «Клиент», «С корзиной» — вычисляются при чтении по
  текущим данным пользователя и `shop.CartItem`.
- Очистка: гость — 7 дней, клиент — 45, клиент с товаром в корзине — 90,
  пустой диалог — 12 часов. Задача `chat.tasks.cleanup_old_conversations`
  выполняется ежедневно через django-q.

## Что нужно в окружении

- `REDIS_URL` — брокер для `CHANNEL_LAYERS` и `CACHES`. Без Redis WebSocket не работает.
- Пакеты `channels`, `channels-redis`, `daphne` должны стоять **в том же venv,
  из которого запускается `runserver`**. Если `channels-redis` нет, HTTP-страницы
  открываются, а WebSocket отдаёт 500 — в браузере это «Соединение прервано».
- ASGI-сервер: в Docker запускается `daphne` (см. `Dockerfile`), локально
  `runserver` тоже поднимает ASGI, потому что `daphne` стоит первым в
  `INSTALLED_APPS`.
- nginx должен пробрасывать `Upgrade`/`Connection` и отдавать `/media/`
  (см. `conf/nginx.conf`).
- Для голосовых нужен `ffmpeg` (в Docker установлен) или `imageio-ffmpeg`.

## Если чат не подключается

1. `python manage.py check` — проверяет канал-слой: сообщит, если
   `channels-redis` не установлен (`chat.E002`) или Redis недоступен (`chat.W001`).
2. В консоли браузера (F12) код закрытия сокета: `1006` — сервер оборвал
   соединение (обычно 500 на рукопожатии), `4403` — нет прав.
3. `POST /chat/start/` должен отвечать `200` и `{"socket_path": "/ws/chat/"}`.
   `403` означает, что браузер не отправил CSRF- или сессионную cookie:
   проверьте `COOKIE_SECURE` (в dev должно быть `False`, иначе куки не сохранятся
   на `http://localhost`) и `ALLOWED_HOSTS` при доступе по IP или туннелю.
4. Если после деплоя WebSocket закрывается с `1011`, проверьте
   `python manage.py migrate --check`: чаще всего не применена миграция.

## Тесты

```bash
python manage.py test chat --settings=chat.test_settings --noinput
```

Тестовая настройка использует SQLite в памяти, `InMemoryChannelLayer` и
`LocMemCache`, поэтому Redis для тестов не нужен. Для голосовых тестов нужен
`ffmpeg`/`imageio-ffmpeg`.
